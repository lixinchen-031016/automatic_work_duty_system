# 自动值班排班系统

基于成员个人课表自动生成值班排班表的桌面应用。上传每位成员的课程表（.xls/.xlsx），系统解析出无课空闲时段，按约束自动生成均衡、无冲突的值班表，并提供甘特图、统计图表与多种格式导出。

- **技术栈**：Python 3.10+ · PySide6（桌面界面） · pandas / openpyxl / xlrd（表格处理） · SQLite（本地存储）
- **纯本地运行**：无需服务器，所有数据保存在本地数据库，关闭程序不丢失
- **界面风格**：类苹果设计语言（macOS 浅色：白色圆角卡片、系统蓝 #007AFF、8pt 间距）

## 功能特性

### 课表管理

- **上传解析**：支持 `.xls` / `.xlsx` 个人课表，自动提取姓名、学号、班级、课程名、教师、地点、周次、节次。
  - 兼容合并单元格、单格多门课程、多门课程之间无空行、教师名断行、混合周次（如 `1,3,5` / `1-10`）等常见格式。
  - **单双周**：`1-16单周` / `1-16双周` / `1-16(单)` / `1-16奇周` 都会展开成真实周次（如 `1,3,5…15`），
    排班与甘特图据此判断该周是否有课。
  - **表头写法**：星期一 / 周一 / 周1 / 礼拜一 / 星期7 均可识别。
  - **格式识别按文件内容而非扩展名**：教务系统导出的文件常被改名（`.xls` 里其实是 xlsx），
    此时按扩展名解析会直接报错、整份课表读不出来；现在会嗅探文件头并自动选择解析器。
  - **字符归一化只做无歧义的部分**：全角数字（`１８`）与全角方括号转半角、清理零宽字符与 CRLF；
    但**刻意不做 NFKC**——它会把罗马数字与全角括号一并改掉（`体育Ⅲ`→`体育III`、`（西肆三楼）`→`(西肆三楼)`），
    导致界面显示的课程名与教务系统不一致。
- **智能去重**：重复上传同一成员（同「学号+姓名」）自动更新其课表，不会产生重复成员。
- **长期特殊安排（修改课表）**：可为成员补充连续多周、每周固定星期/时段的课表外占用，
  支持添加、编辑、删除与原因备注；自动排班、甘特图和手动微调统一避让。
- **安全删除**：删除成员需确认，确认框默认聚焦「取消」，防止误删。

### 智能排班

- **硬约束**（绝不允许违反）：
  - 值班时段内无课（时段块的每一节都无课才算空闲）；
  - 避开长期特殊安排；
  - 避开请假日；
  - 每人每天最多值 1 次（可调）；
  - 每人每周不超过设定上限。
- **软目标**（尽量均衡）：三级贪心均衡——总次数 → 本周次数 → 当天次数，优先安排累计次数最少的成员。
- **动态覆盖均衡**：优先安排当前覆盖最少的星期和时段，保证周一至周五每天都有人值班（避免"周五永远没人"的问题）。
- **按周增量排班**：每次只重排「值班周范围」内的周，范围外的历史排班保留并计入均衡基数——每周只排本周的班，长期下来总量依然均衡，且每周基于最新课表 / 请假情况独立生成。
- **结果持久化**：排班结果存入 SQLite，程序关闭后不丢失，重新打开自动恢复。

### 请假 / 临时占用

- 按成员 + 周次 + 星期登记请假及原因，同一天重复登记自动覆盖。
- 排班自动避让请假日；甘特图中当天整行标红。
- 一键**导出请假记录**（Excel：成员、学号、周次、星期、日期、原因）。

### 长期特殊安排（修改课表）

- 在「成员课表」页新增成员的特殊安排：连续周范围 + 星期 + 一个或多个时段块 + 原因。
- 同一安排重复保存会覆盖原因；选中后可修改周次、星期、时段和备注，也可直接删除。
- 这类安排在自动排班、甘特图和手动微调中均按硬冲突处理，甘特图显示为紫色「其他安排」。

### 手动微调

- 双击值班排班表任一时段单元格，弹出微调对话框，可**换人 / 新增 / 移除**。
- 候选列表实时标注不可用原因（有课 / 其他安排 / 请假 / 当天已值班 / 本周已达上限）。
- 周上限为软约束：饱和时可"知情越限"换人；课程冲突、特殊安排、请假、每天一次始终拦截。
- 支持撤销/重做手动微调（最多 50 步）；切换成员或重新生成排班后清空历史，避免跨上下文误操作。

### 可视化

- **空闲甘特图**：行=星期×时段，列=成员。颜色含义：
  - 🟩 绿色=空闲　⬜ 灰色=有课　🟦 蓝色=已排值班　🟧 橙色=全员空闲　🟥 红色=请假　🟪 紫色=其他安排
  - 甘特图按自然日期周展示：正常工作日、放假日和周末补课日都归入其真实所在周；最右侧汇总列显示各时段空闲人数，支持按周切换、按星期/时段筛选。
  - 可导出带填充色的 Excel 甘特图。
- **学期日历覆盖**：通过日期选择框登记法定假日 `off` 与周末补课 `class maps_to` 映射，支持一键生成互补调休项，也可从内置 2025/2026 或在线 `chinese-days` 数据导入国家法定节假日与调休上班日并预览确认。排班仍按逻辑周次运行，导出与甘特图显示真实日期；原放假日标红，补课日按所代表的逻辑工作日课表判定忙闲，并自动加入可排日而无需勾选周末。
- **统计图表**：三张柱状图——各成员值班总次数、每周值班人次、各成员请假天数，一键导出高清 PNG。

### 导出

| 格式 | 内容 | 说明 |
| --- | --- | --- |
| Excel（多 Sheet） | 值班总表 / 值班明细 / 值班统计 / 无人可用时段 | 表头着色、列宽自适应、含日期列 |
| CSV | 值班明细 | UTF-8 BOM，Excel 可直接打开 |
| PNG 图片 | 值班总表渲染图 | 高清 2x，方便发群通知 / 打印 |
| Excel（请假） | 请假记录 | 从请假登记卡片导出 |
| Excel（甘特图） | 忙闲矩阵 | 带填充色，行=时段、列=成员，冻结首列 |
| PNG（统计图） | 三张统计柱状图 | 纵向拼接，高清 2x |

- **导出前可选周数**：导出值班表（Excel/CSV/PNG）时弹窗选择"全部周"或某一周，文件名自动带周次（如 `值班排班表_第5周.xlsx`）。
- **周次自动换算日期**：设置学期起始日（第一周周一）后，排班表自动显示每条值班的具体日期，支持跨月、跨年。

### 易用性细节

- 参数（周范围、星期、时段、上限、种子、起始日等）经 QSettings 持久化，重启自动恢复。
- 成员列表支持按姓名、学号、班级即时搜索与班级筛选，过滤仅作用于视图层。
- 「清空排班…」支持仅清空当前所选周范围或清空全部安排。
- 修改参数或成员后，旧结果标记"⚠ 可能过期"，提示重新生成。
- 双击成员列表直接跳转「成员课表」页并定位该成员。
- 空数据时有引导提示（如何上传、如何生成）。
- **数据库存储位置可自定义**：左侧「数据存储」卡片可更改数据库位置——现有数据自动复制到新位置（原文件保留）；若目标目录已有同名数据库文件，则安全切换为使用该文件（可用于恢复备份），不覆盖任何数据。
- 固定随机种子可复现同一份排班，改种子可换一版均衡方案。

## 安装与运行

### 环境要求

- Python 3.10 及以上（开发环境为 3.13）
- macOS / Windows / Linux 桌面环境

### 安装步骤

```bash
# 1. 进入项目目录
cd automatic_work_duty_system

# 2. 创建并激活虚拟环境
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 3. 安装依赖
pip install -r requirements.txt
```

依赖清单（`requirements.txt`）：

```
xlrd>=2.0.1      # .xls 解析
openpyxl>=3.1    # .xlsx / Excel 导出
pandas>=2.0      # 表格构建
PySide6>=6.7     # 桌面界面
certifi>=2024.2  # 在线更新国家调休数据的 TLS 根证书
```

### 启动

```bash
.venv/bin/python app.py          # Windows: .venv\Scripts\python app.py
```

> **注意（TRAE / 部分终端环境）**：若启动报 Qt 或 import 错误，请使用
> `env -u PYTHONHOME -u PYTHONPATH .venv/bin/python app.py`
> 以清除干扰的环境变量（仅 macOS/Linux 需要；Windows 正常执行 `.venv\Scripts\python app.py` 即可）。

## 快速上手

1. **上传课表**：左侧「成员」区点击「上传成员课表…」，选择每位成员的 .xls/.xlsx 课表文件（可一次多选）。成员列表出现姓名与课程数即解析成功。
2. **设置参数**：确认值班周范围、值班星期、值班时段、每时段人数、每周/每天上限；填写「学期起始日」（第一周周一的日期，用于周次换算日期）。
3. **补充不可值班信息**（可选）：在「成员课表」页为长期固定安排点击「添加安排…」；临时变化点击「添加请假…」。
4. **生成排班表**：点击左侧「生成排班表」。摘要区显示人次、缺口、均衡极差等结果。
5. **导出发布**：点击「导出 Excel / CSV / 图片」，选择要导出的周数，即可发布到群里。每周推进时把周范围改成下一周，重新生成即可——历史周不受影响。

### 推荐的按周推进工作流

```
第 1 周开学：周范围 1–18，一次性生成整学期
每周固定动作：
  ① 有新的长期安排 → 修改课表；临时变化 → 请假登记
  ② 周范围改为「本周 至 本周」（如 5 至 5）
  ③ 点击「生成排班表」→ 只重排本周，其他周保留且计入均衡
  ④ 导出本周值班表（选周=本周）发群
```

## 排班规则详解

### 硬约束（算法保证，手动微调也不可越过）

1. **无课冲突**：值班时段块内的每一节都不能有课（如值 1-2节 需第 1、2 节都无课）。
2. **特殊安排冲突**：连续周范围内、指定星期和时段块有课表外安排的成员不可安排值班。
3. **请假日不可值班**：登记请假的成员当天任何时段不参与排班。
4. **每天一次**：每人每天最多值 1 次班（参数可调，默认 1）。
5. **每周上限**：每人每周不超过设定次数（默认 3）。

### 软目标（贪心均衡）

- 安排顺序按三级优先级挑选成员：**累计总次数最少 → 本周次数最少 → 当天次数最少**。
- 任务处理顺序采用**动态覆盖均衡**：优先安排当前覆盖最少的（星期 × 时段）组合，确保每天都排满、避免某天整天空缺。
- 同覆盖度时再按**时段稀缺度**排序（可选人数少的时段先占），最后按随机种子决定，保证同参数可复现。
- 贪心结束后对剩余缺口做**链式挪动修复**：把已排成员挪到缺人时段、再回填其原时段（深度 2，预算受限），实测在「人多班少」场景可把缺口从 50 降到 19 个；容量本身不足时不做无意义搜索。
- 缺口口径统一由 `compute_gaps()` 计算（排班范围内人数不足 `每时段人数` 的时段），生成、重启恢复、手动微调三处完全一致。

### 算法质量认证（为什么不改成网络流）

`test_optimality.py` 用最大流建模求出**覆盖最优值**（该值本身对应一个合法排班），
以此为基准对比生产算法：

| 场景（18 周 × 5 天 × 5 时段） | 需求 | 最优 | 生产算法 | 覆盖率 | 成员次数极差 |
| --- | --- | --- | --- | --- | --- |
| 20 人 · 每时段 2 人 | 900 | 874 | 873 | 99.9% | **4**（纯最大流解 36） |
| 15 人 · 每时段 2 人 | 900 | 793 | 787 | 99.2% | 6（纯最大流解 6） |
| 25 人 · 每时段 3 人 | 1350 | 1289 | 1276 | 99.0% | 14 |
| 30 人 · 每时段 2 人 | 900 | 899 | 899 | **100%** | — |

结论：覆盖率已达最优值的 99% 以上，而**纯最大流解会严重破坏均衡**（同一网络有大量等价最优解，
取到的解可能有人 54 次、有人 18 次）。要让网络流同时保证均衡，必须写成带凸费用的最小费用流，
实现复杂度大幅上升，换来的覆盖率收益不足 1% —— 因此保留现有启发式，并用测试把这个结论固化。

### 按周增量排班

- 生成时只**重排**「值班周范围」内的周；范围外已有排班：
  - 原样保留在结果和数据库中；
  - 计入总次数均衡基数（历史值多的成员本周少排）。
- 由此实现"每周生成每周对应的值班表，且和以前互不影响"。

### 手动微调

- 双击值班表单元格 → 对话框显示当前值班人、可换/可增候选。
- 候选标注原因：可换（空）/ 该时段有课 / 其他安排 / 请假 / 当天已值班 / 本周已达上限。
- 「本周已达上限」为知情越限项（软约束），选中后界面提示风险；其余为硬约束不可选。
- 应用后立即重写数据库并刷新统计。

## 数据存储

单一 SQLite 文件 `duty_system.db`（默认位于程序目录，可通过左侧「数据存储」卡片自定义位置，自动创建）。
数据库启用 **WAL** 模式并带索引；「更改位置」走 SQLite 在线备份 API（`Database.backup_to()`），
不是文件复制——WAL 模式下最新数据与 schema 可能还在 `-wal` 文件里，直接复制主库会得到损坏副本。

| 表 | 字段 | 说明 |
| --- | --- | --- |
| `members` | id, student_id, name, class_name, term, file_name, course_count | 成员（student_id+name 唯一，重复上传更新） |
| `courses` | id, member_id, course_name, teacher, location, weeks, weekday, sessions | 成员课表课程记录 |
| `special_arrangements` | id, member_id, week_start, week_end, weekday, session_list, reason | 长期特殊安排（修改课表） |
| `duty_assignments` | id, week, weekday, block, member_id, member_name；UNIQUE(week, weekday, block, member_id) | 值班安排 |
| `leaves` | id, member_id, week, weekday, reason；UNIQUE(member_id, week, weekday) | 请假记录 |

- **存储位置**：自定义位置记录于 QSettings（`database/path`），启动时优先使用；若该路径已不存在（如磁盘移除），自动回退到程序目录下的默认数据库。
- **迁移安全**：更改位置时现有数据复制到新位置、原文件保留；所选目录已有同名数据库文件时，切换为使用该文件而不覆盖（可用于在多台设备间搬运/恢复数据）。
- 删除成员时其课程、特殊安排、值班、请假记录级联删除。
- 界面参数（不含排班结果）另存于 QSettings。
- 备份：直接复制 `duty_system.db` 文件即可完整备份全部数据。

## 扩展与维护指南

### 新增一条排班约束（如「同一成员不连续两天值班」）

1. 在 `duty_system/scheduler.py` 的 `ScheduleContext` 中补充计数与 `reason()` 判定，
   并新增一个原因常量（如 `REASON_CONSECUTIVE`）。
2. 若属于「可手动越限」的软约束，把常量加入 `SOFT_REASONS`；硬约束不必登记。

**不需要**再改第二处：自动排班、缺口修复、手动微调候选、界面校验都走同一个
`reason()`，这是本次重构收敛掉的主要风险（此前三处各写一套过滤条件）。

### 新增一个可持久化参数

在 `MainWindow._param_specs()` 里加一行 `("spin", self.xxx, "xxx", 默认值)` 即可，
读写共用同一份声明；同时把该参数接进 `_current_config()` 才会参与排班。

### 新增一种导出格式

在 `exporter.py` 加纯函数返回 `bytes`，界面按钮改用
`MainWindow._export_bytes(...)`，即自动获得「后台生成 + 状态栏提示」。

### 修改课表解析器（parser.py）

**改之前先读这句话**：`samples/desensitized/` 下的九份 `.xls` 来自真实教务系统导出
（37/57/57/49/39/45/40/30/36 门），`test_parser_robustness.py` 里有它们的黄金基线
（姓名/学号/学期/班级/院系 + 每条课程记录逐字段校验）。
改动解析器后必须保证这些基线不变——它们是判断「优化」还是「改坏」的唯一依据。

每份课表末尾还有一行教务系统自带的备注（`课程名 教师 周次周;` 清单；集中实践也可能是
`课程名 周次周;`），
`test_real_samples_note_row_agrees_with_parsed_courses` 会用它反查解析结果，
所以「少读一门课」「教师读错」这类问题会自动被测试抓住。备注行中网格未覆盖的周次，
若同一门课在网格中有唯一的星期/节次，会自动继承该时间并补全周次；只有完全无法定位、
或同名课程存在多套时间时，才进入 `whole_week_courses` 并按整周避让。

**关于样例的隐私处理**：原始课表含姓名与学号，只留在本地
（`.gitignore` 忽略 `samples/*.xls`）。提交进仓库的是 `samples/desensitized/`
下的脱敏副本——由 `tools/desensitize_samples.py` 用**等长 UTF-16LE 字节替换**
生成，只改姓名与学号，课程名/周次/节次/地点/课程数与原文件逐字段一致，
因此仍保留真实布局（合并单元格、SST 共享、换行方式）带来的解析难度。

拿到新的原始课表后：

```bash
python tools/desensitize_samples.py          # 生成/刷新脱敏样例
python tools/desensitize_samples.py --check   # 校验脱敏样例与原始文件一致
pytest -q                                    # 确认基线
```

脚本会自动断言：文件长度不变（结构未坏）、真实姓名/学号零残留、
脱敏样例可解析且课程数据与原始文件一致，并刷新 `manifest.json`。
**不要手工改脱敏样例**——`test_sample_privacy.py` 会拿 manifest 校验并在不一致时失败。

排查解析问题时按这个顺序看：

1. `_split_segments` / `_split_lines_by_week_line`：单元格怎么切成多门课程
   （空行分隔为主；无空行时按「周次行」聚合，并用地点特征词区分「上一门的地点」与「下一门的课程名」）；
2. `WEEK_SESSION_RE`：周次行正则（周次/单双周/`[周]` 标记/节次书写方式）；
3. `_split_name_teacher` + `TEACHER_LIST_RE` / `TEACHER_RE`：课程名与教师拆分（职称表在 `TEACHER_TITLES`；多人授课与括号换行都由这里处理）；
4. `parse_weekday_header`：星期表头写法；
5. `parse_weekdays` 用 `parse_weekday_header` 的别名规则，表头识别不到会导致整份课表 0 条。

新增一种写法时：先在 `test_parser_robustness.py` 加一条失败用例（跑一遍确认它是红的），
再改解析器让用例通过，最后跑 `pytest -q` 确认九份样例的基线没有漂移。

### 新增一个数据库字段或表

1. 修改 `duty_system/database.py` 的 `SCHEMA`（新库直接建）。
2. 在 `MIGRATIONS` 追加 `(版本号, [DDL 列表])`——**必须**，否则已存在的用户库不会变更
   （老写法 `CREATE TABLE IF NOT EXISTS` 对既有库静默跳过，字段加了也不生效）。

### 性能注意事项（有实测数据支撑）

实测环境：macOS / Apple Silicon，300 名成员 × 40 门课 × 18 周。

| 环节 | 优化前 | 优化后 | 手段 |
| --- | --- | --- | --- |
| 排班（20 人 / 每时段 2 人） | 50 个缺口 | **19 个缺口** | 时段稀缺度排序 + 缺口链式修复 |
| 排班（300 人） | 0.085s | 0.139s | 增加了覆盖优化，仍在 0.2s 内 |
| 排班页刷新（300 人） | 134ms | **19ms** | 单元格复用 + 用 `itertuples` 批量取数替代逐格 `df.iat` |
| 甘特刷新（300 人） | 96ms | **16ms** | 复用 `QTableWidgetItem`；忙时表随课表缓存；单元格写入前先用 Python 侧状态缓存比对，无变化则完全不碰 Qt 属性（Qt 属性读取是原瓶颈） |
| 甘特刷新（30 人） | — | **1.4ms** | 同上 |
| 重建忙时表 | 每次刷新都建（54ms） | 缓存命中即 0ms | `MainWindow.busy_map()`，写操作后失效 |
| 窗口卡顿 | 生成/导出期间界面无响应 | 无阻塞 | `run_async()` 线程池 + 忙碌提示 |
| 重复生成写入 | 整周删除重建 | 只增删差异行 | `sync_assignments_for_weeks()` |
| 缺口诊断 | 无此能力 | 一次诊断 + 缓存 | `diagnose_gaps()`，按排班结果缓存，重复刷新 0 开销 |
| 统计重算 | O(成员 × 排班) | O(排班)（300 人 0.13ms） | 一次遍历 + `Counter` |

剩余可做项（当前规模下不构成问题，且已有测试兜住回退）：

- 甘特图仍是 `QTableWidget`，成员数到千级（>1000）时可改用 `QTableView` + 自定义 model/委托；
- 排班算法是启发式，覆盖率已认证 ≥99%（见上文），无需改成最小费用流；
- 排班计算仍在内存里全量进行，若将来支持跨学期超大跨度可考虑分周流式计算。

## 常见问题

**Q：为什么周五（或某天）排不出值班？**
早期版本按周一→周五固定顺序排班，前几天耗尽每周额度导致周五无人。现已改为动态覆盖均衡，优先安排覆盖最少的星期。若仍出现缺口，请查看「值班统计」页的「无人可用时段」清单——表示该时段全员有课或请假，属客观不可排。

**Q：生成的排班表会覆盖以前的吗？**
不会。只重排「值班周范围」内的周；范围外的历史排班保留并计入均衡基数。想整学期重排，把周范围设为整个学期再生成即可。

**Q：关掉程序后排班结果还在吗？**
在。结果实时写入 `duty_system.db`，重新打开程序自动恢复，无需重新生成。

**Q：修改了参数/成员后旧结果还能用吗？**
能看，但摘要区会提示"⚠ 排班参数或成员已变化，结果可能过期"，建议重新生成。

**Q：导出的 Excel 周次能换成具体日期吗？**
能。左侧设置「学期起始日」（第一周周一）后，明细表、透视表、Excel、CSV、PNG 均自动附带日期列，支持跨月/跨年。

**Q：双击值班表单元格没反应？**
请双击右侧「值班排班表」页的表格内容单元格（表头的周次/星期/日期列除外），会弹出手动微调对话框。

**Q：随机种子是干什么的？**
平手时决定分给谁。固定种子 = 同样参数生成完全相同的排班（可复现）；换一个种子 = 换一版同样均衡的方案。

**Q：能在 Windows 上运行吗？**
能，无需修改任何代码。已逐项验证：依赖（PySide6/pandas/xlrd/openpyxl）均提供 Windows 官方轮子；界面字体全部使用 Qt 默认字体（无 macOS 专用字体声明，Windows 自动回退 Segoe UI / 微软雅黑）；数据库路径基于 `Path(__file__)`，QSS 图标路径已做 `as_posix()` 处理；CSV 带 UTF-8 BOM，Windows Excel 双击打开不乱码；全项目无平台专用 API。安装与启动：

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
.venv\Scripts\python app.py
```

Windows 使用注意事项：

1. **源码运行建议放在用户可写位置**（如 `D:\duty_system`）。打包版若放在 `C:\Program Files` 等不可写目录，数据库会自动回退到 `%LOCALAPPDATA%\DutySystem\`；
2. **参数持久化位置不同**：Windows 存于注册表 `HKCU\Software\DutySystem\DutyScheduler`（macOS 为偏好设置文件），功能一致，删除对应注册表项即可重置参数；
3. Python 版本需 **3.10 及以上**（代码使用 `int | None` 联合类型语法）。

**Q：如何在终端/TRAE 环境运行脚本？**
若遇 Python 环境变量冲突（Qt 报错或 import 异常），使用：
`env -u PYTHONHOME -u PYTHONPATH .venv/bin/python app.py`
